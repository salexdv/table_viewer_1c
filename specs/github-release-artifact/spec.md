# github-release-artifact: публикация HTML-сборки в GitHub Release

## 1. Контекст и проблема

Production-сборка проекта создаёт автономный `dist/index.html`, но готовый файл нужно собирать вручную после
каждого релиза. Опубликованный GitHub Release должен автоматически получать проверенную HTML-сборку, которую
можно скачать и использовать без локальной установки Node.js и зависимостей проекта.

## 2. Область изменений

Добавляется GitHub Actions workflow для сборки и публикации HTML, а README дополняется описанием готового
артефакта. Команда `npm run build`, формат `dist/index.html`, публичный JavaScript API, события 1С и поведение
просмотрщика не изменяются.

## 3. Поведение

### 3.1. Основной сценарий

1. При публикации GitHub Release workflow получает исходники соответствующего релиза.
2. В окружении Node.js 20 зависимости устанавливаются через `npm ci` по `package-lock.json`.
3. Команда `npm run build` создаёт и проверяет автономный `dist/index.html`.
4. Файл копируется под стабильным именем `table_viewer.html` и прикладывается к опубликованному релизу.
5. При ручном запуске workflow тот же файл сохраняется как Actions Artifact `table_viewer-html`, но не
   прикладывается ни к одному релизу.

### 3.2. Граничные случаи и ошибки

- Ошибка получения исходников, установки зависимостей, сборки, копирования или загрузки завершает workflow с
  ошибкой.
- Повторный запуск для того же релиза заменяет существующий `table_viewer.html`, не создавая одноимённых
  дубликатов.
- Workflow не создаёт теги и релизы и не изменяет содержимое опубликованного релиза, кроме одноимённого asset.
- Для загрузки используется встроенный `github.token`; отдельные секреты не требуются.

## 4. Публичные контракты

- Каждый успешно обработанный опубликованный GitHub Release содержит asset `table_viewer.html`.
- Ручной запуск создаёт Actions Artifact `table_viewer-html`, содержащий `table_viewer.html`.
- Production-контракт проекта остаётся прежним: `npm run build` создаёт единственный автономный
  `dist/index.html`.

## 5. Критерии приёмки

- [ ] Workflow запускается для события `release.published` и вручную через `workflow_dispatch`.
- [ ] Workflow использует Node.js 20, `npm ci` и `npm run build`.
- [ ] При релизном запуске `table_viewer.html` загружается в указанный GitHub Release с заменой существующего
  одноимённого asset.
- [ ] При ручном запуске `table_viewer.html` доступен как Actions Artifact `table_viewer-html`, а релизы не
  изменяются.
- [ ] README описывает готовый release asset и ручной проверочный запуск.
- [ ] Локальная production-сборка и её проверки проходят.

## 6. Вне области

- Автоматическое создание GitHub Release или тега.
- Публикация архивов, checksum-файлов, npm-пакетов или GitHub Pages.
- Изменение содержимого и имени локального `dist/index.html`.
- Изменение логики просмотрщика, публичного JavaScript API или событий 1С.
