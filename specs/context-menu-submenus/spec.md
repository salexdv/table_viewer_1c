# context-menu-submenus: Пользовательские подменю контекстного меню

## 1. Контекст и проблема

Публичные методы `addContextMenuItem` и `addContextMenuSeparator` позволяют создавать только плоскую
последовательность пользовательских команд. Интеграции с 1С нужен способ объединять связанные команды во
вложенные меню, сохраняя порядок регистрации и существующий контракт событий.

## 2. Область изменений

Добавляются регистрация одноуровневых пользовательских подменю, направление пунктов и разделителей в выбранное
подменю, browser-тесты и документация JavaScript API и интеграции с 1С.

## 3. Поведение

### 3.1. Основной сценарий

- `addContextMenuSubmenu(name)` регистрирует подменю в текущей позиции верхнеуровневой последовательности и
  возвращает `true`.
- Необязательный третий аргумент `addContextMenuItem(title, eventName, submenuName)` направляет пункт в ранее
  зарегистрированное подменю. Без него пункт остаётся на верхнем уровне.
- Необязательный аргумент `addContextMenuSeparator(submenuName)` направляет разделитель в ранее
  зарегистрированное подменю. Без него разделитель остаётся на верхнем уровне.
- Позиция подменю определяется вызовом `addContextMenuSubmenu`; последующее добавление дочерних элементов её не
  меняет. Порядок элементов внутри подменю соответствует порядку адресованных ему вызовов.
- Подменю использует те же открытие, позиционирование, закрытие и ARIA-атрибуты, что и штатные подменю.
- Пользовательские элементы выводятся только для ячеек данных. Регистрация сохраняется при `setData`, но
  очищается при `destroy` и повторном `init`.

### 3.2. Граничные случаи и ошибки

- Имя подменю должно быть непустой строкой, сравнивается без преобразования и одновременно служит видимой
  подписью. Повторное имя возвращает `false` и не меняет регистрацию.
- Пункт или разделитель с неизвестным, пустым, равным `null` либо имеющим неверный тип именем подменю возвращает
  `false`. Только отсутствующий аргумент или `undefined` означает верхний уровень.
- Пустое подменю и подменю, содержащее только разделители, не выводится.
- Ведущие, замыкающие и повторяющиеся разделители не создают лишних линий отдельно на каждом уровне.
- Названия подменю и пунктов выводятся через `textContent`; пользовательский HTML не вставляется.
- До инициализации приложения и после `destroy` публичные методы возвращают `false`.

## 4. Публичные контракты

На `window` добавляется и расширяется API:

```js
addContextMenuSubmenu(name) // boolean
addContextMenuItem(title, eventName, submenuName?) // boolean
addContextMenuSeparator(submenuName?) // boolean
```

Контракт события `{ event, params }`, payload обычных и ссылочных ячеек, формат данных, Settings и автономная
production-сборка не меняются.

## 5. Критерии приёмки

- [ ] Подменю регистрируется один раз, занимает позицию вызова и принимает адресованные пункты и разделители.
- [ ] Некорректные и неизвестные имена отклоняются без частичной регистрации.
- [ ] Плоские элементы и несколько подменю выводятся в заданном порядке только для ячеек данных.
- [ ] Пустые подменю и лишние разделители не создают пустых пунктов или линий.
- [ ] Подменю открывается и закрывается существующими способами и остаётся в границах окна.
- [ ] Выбор дочернего пункта отправляет прежний payload для обычной или ссылочной ячейки.
- [ ] Подписи безопасно выводятся как текст, жизненный цикл регистрации не меняется.
- [ ] API и пример 1С документированы; полный локальный гейт проходит.

## 6. Вне области

- Вложенность подменю глубже одного уровня.
- Удаление, очистка, переименование и изменение зарегистрированных элементов.
- Отдельный внутренний идентификатор, отличный от видимой подписи подменю.
- Изменение внешнего вида или полная клавиатурная навигация меню.
