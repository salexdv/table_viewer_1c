# nested-table-tabs: Вложенные таблицы во вкладках

## 1. Контекст и проблема

Ячейка сейчас может быть скаляром или ссылкой `{ label, ref }`. Таблицы значений внутри ячеек приходится
показывать вне просмотрщика. Нужен новый тип `{ label, table }`, который открывает вложенную таблицу в отдельной
закрываемой вкладке, не отправляя событие перехода по ссылке в 1С.

## 2. Область изменений

Расширяются разбор и валидация данных, модель состояния интерфейса, отображение ячеек, навигация по вкладкам,
автотесты и документация формата. Вложенность таблиц поддерживается на произвольную глубину.

## 3. Поведение

### 3.1. Данные

- `Cell = scalar | { label: string, ref: string } | { label: string, table: Table }`.
- `table` содержит один объект того же формата `Table`, который используется в корневом массиве `tables`.
- `ref` и `table` взаимоисключающие. Ошибка сообщает полный путь к ячейке.
- Все вложенные таблицы валидируются атомарно при `init` и `setData`, но состояние вкладки создаётся только при
  первом открытии.
- Одинаковые `table.id` в разных ячейках допустимы. Циклические ссылки в JS-объектах отклоняются.
- Поиск, сортировка, фильтры и подпись ячейки используют `label`.

### 3.2. Вкладки

1. Исходные таблицы образуют постоянную исходную вкладку.
2. Клик по `{ label, table }` открывает вложенную таблицу справа и активирует её.
3. Повторный клик по той же ячейке активирует уже открытую вкладку; разные ячейки всегда являются разными
   источниками, даже если их `table.id` совпадает.
4. Вложенная таблица может открыть следующий уровень. Уже открытые дочерние вкладки не закрываются вместе с
   родительской.
5. Вкладки сохраняют собственные фильтры, сортировку, размеры, прокрутку, раскрытие дерева и выделение.
6. Исходная вкладка не закрывается. После закрытия активной вложенной вкладки выбирается соседняя справа, а при
   её отсутствии — слева. Повторное открытие закрытой вкладки создаёт новое состояние.
7. Панель вкладок находится под общей панелью инструментов и скрыта, пока вкладка одна.

Заголовок вложенной вкладки берётся из непустого `table.name`, затем из `label`, затем используется `Таблица`.
Исходная вкладка называется именем единственной исходной таблицы либо `Основные таблицы`.

### 3.3. Область состояния

- Поиск, настройка колонок и табличные команды панели работают с активной вкладкой.
- Тема, перенос текста, настройки представления значений и пользовательское меню общие для приложения.
- `setData` закрывает все вложенные вкладки и создаёт новую исходную вкладку.
- Переключение и закрытие отменяют отложенную отрисовку скрываемых таблиц.

### 3.4. События и ошибки

- Клик вложенной таблицы не формирует `EVENT_ON_LINK_CLICK` и не добавляет новый тип события.
- Пользовательский пункт контекстного меню получает для такой ячейки `{ value: label }`; содержимое `table`
  через мост не передаётся.
- Ошибка в любой вложенной таблице отклоняет весь новый набор данных по существующим атомарным правилам.

## 4. Публичные контракты

Новых функций на `window` нет. `getSettings`, `setSettings`, `setTableCollapsed`, `setTreeExpanded`, `expandAll`
и `collapseAll` продолжают относиться только к исходным таблицам независимо от активной вкладки. Настройки и
состояние вложенных вкладок не входят в Settings и живут только в памяти документа.

## 5. Критерии приёмки

- [ ] Новый тип ячейки валидируется на любой глубине и отображается как ссылка по `label`.
- [ ] Клик открывает или активирует нужную вкладку без события 1С.
- [ ] Одинаковые `table.id` в разных ячейках не объединяют вкладки.
- [ ] Переключение сохраняет локальное состояние, закрытие и выбор соседней вкладки работают по контракту.
- [ ] Исходная вкладка и прежний публичный API остаются стабильными.
- [ ] `setData` сбрасывает вкладки, а старые скалярные и ссылочные ячейки работают без изменений.
- [ ] Полный локальный гейт `npm test` проходит, production остаётся self-contained и ES2015-совместимым.

## 6. Вне области

- Сохранение открытых вкладок и их состояния в Settings.
- Публичный API открытия, закрытия или переключения вкладок.
- Передача содержимого вложенной таблицы в 1С через события.
