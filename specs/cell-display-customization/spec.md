# cell-display-customization: настраиваемое отображение значений ячеек

## 1. Контекст и проблема

Просмотрщик всегда выводит исходное текстовое представление значения и не позволяет интеграции 1С визуально
отмечать отрицательные числа, заменять представление отдельных значений или различимо показывать пустые ссылки.

## 2. Область изменений

- Пять новых функций плоского API на `window` для настройки текста и цвета ячеек.
- Единое вычисление визуального представления при отрисовке обычных, закреплённых и виртуальных строк.
- Документация JavaScript API и примеры интеграции с 1С.
- Unit-тесты правил представления и browser smoke публичного контракта.

## 3. Поведение

### 3.1. Основной сценарий

- До настройки отрицательные значения отображаются штатным цветом.
- Цвет отрицательных применяется к конечным JSON-числам меньше нуля и строкам, которые существующая модель
  распознаёт как отрицательные числа или проценты.
- Представление и цвет задаются для точного скалярного значения с учётом типа: число `0` не совпадает со
  строкой `"0"`.
- Точное правило цвета имеет приоритет над общим цветом отрицательных.
- При включённом показе ссылка с `ref`, оканчивающимся ровно на 32 нуля, выводится некликабельным серым текстом.
  Для `e1cib/data/<тип>?ref=...` текст равен `<<тип> (пустая)>`; для другого формата — `<пустая ссылка>`.
- Цвет пустой ссылки имеет наивысший приоритет. Его исходное значение — `#6d7d91`.
- Настройки применяются немедленно, сохраняются при `setData` и сбрасываются новым `init` или `destroy`.

### 3.2. Граничные случаи и ошибки

- Целевое значение точного правила — только `string | number | boolean | null`; число должно быть конечным.
- Пустая строка является допустимым пользовательским представлением.
- `null` вместо представления или цвета удаляет соответствующее правило; для цвета пустой ссылки возвращает
  стандартный серый, а для отрицательных отключает окрашивание.
- Цвет должен быть непустой валидной CSS-строкой. Некорректный аргумент возвращает `false`, не меняет настройки
  и не перерисовывает таблицы.
- Показ пустых ссылок определяется только суффиксом `ref`; исходный `label` не влияет на классификацию.
- Пользовательские тексты выводятся только через `textContent` или текстовые DOM-узлы.

## 4. Публичные контракты

```js
setNegativeNumberColor(colorOrNull)
setCellValuePresentation(value, presentationOrNull)
setCellValueColor(value, colorOrNull)
setShowEmptyReferences(enabled)
setEmptyReferenceColor(colorOrNull)
```

Каждый метод экспортируется непосредственно на `window`, возвращает `true` при успехе и `false`, если приложение
не создано или аргументы некорректны. `setShowEmptyReferences` приводит аргумент к boolean.

Настройки меняют только текст, `title`, цвет и кликабельность специально показанной пустой ссылки. Поиск,
фильтры, сортировка, списки значений, типы колонок, ширины, итоги и payload событий продолжают использовать
исходные данные. Подсветка поиска строится только для запроса, совпавшего с исходной ячейкой, и видимых фрагментов
итогового текста. Настроенный цвет сохраняется при выделении ячейки и внутри поисковой подсветки.

Формат `Data`, очередь `{ event, params }`, события 1С и автономная production-сборка не меняются.

## 5. Критерии приёмки

- [ ] Все пять функций доступны на `window`, валидируют аргументы и немедленно обновляют видимые таблицы.
- [ ] Числа, числовые строки и проценты меньше нуля получают заданный общий цвет; без вызова цвет не меняется.
- [ ] Точные правила различают тип значения, безопасно меняют текст и переопределяют общий цвет отрицательных.
- [ ] Пустые ссылки получают требуемый текст и цвет, не являются ссылками и не отправляют событие клика.
- [ ] Обычные ссылки и все операции над исходными данными сохраняют прежний контракт.
- [ ] Настройки переживают `setData`, сбрасываются повторным `init` и покрыты unit/browser тестами.
- [ ] `npm test` проходит, production остаётся одним self-contained ES2015 HTML-файлом.

## 6. Вне области

- Правила по таблице, строке или колонке и сопоставление по шаблонам.
- Настройка фона, шрифта, итогов, заголовков или значений в панелях фильтра.
- Изменение входного JSON, payload событий или открытие ссылок самим просмотрщиком.
