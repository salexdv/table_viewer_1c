# dark-theme: Тёмная тема и API переключения

## 1. Контекст и проблема

Просмотрщик использует только светлую палитру. Интеграции 1С нужен управляемый тёмный режим, который можно
включить программно, переключить из интерфейса и сохранить вместе с остальными настройками представления.

## 2. Область изменений

- Полная тёмная палитра всех постоянных и динамических поверхностей просмотрщика.
- Компактная кнопка переключения темы в общей панели.
- Публичная функция `setTheme`.
- Поле темы в Settings версии 1 и документация интеграции.
- Unit- и browser-проверки нового контракта.

## 3. Поведение

### 3.1. Основной сценарий

- Исходной темой нового приложения является `light`; системная тема операционной системы не учитывается.
- `setTheme('dark')` и `setTheme('light')` немедленно меняют оформление без перерисовки данных.
- Кнопка в отдельной группе общей панели переключает текущую тему. В светлом режиме она предлагает включить
  тёмную тему, в тёмном — светлую.
- `getSettings()` всегда включает корневое поле `theme`, а `setSettings()` и `Data.settings` применяют его как
  часть Settings версии 1.
- Отсутствующее в patch поле `theme` сохраняет текущую тему. Старый полный снимок без поля темы также остаётся
  валидным и при применении не меняет текущую тему.
- Успешный `setData` без `settings` сбрасывает тему в `light`; встроенные настройки применяются поверх этого
  значения. Новый `init` и `destroy` также возвращают светлое оформление.

### 3.2. Граничные случаи и ошибки

- Тема принимает только точные строки `light` и `dark`; другое значение отклоняется.
- Некорректный вызов `setTheme` возвращает `false` без изменения состояния.
- Ошибка `setSettings` или `setData` не должна частично менять текущую тему.
- После `destroy` класс тёмной темы снимается с документа, а вызов `setTheme` возвращает `false`.
- Пользовательские цвета значений ячеек имеют прежний приоритет и не заменяются палитрой темы.

## 4. Публичные контракты

```js
Theme = 'light' | 'dark'
Settings = { version?: 1, theme?: Theme, globalFilter?: string, tables?: TableSettings[] }

setTheme(theme) // boolean
```

Полный снимок `getSettings()` имеет `version: 1` и всегда содержит `theme`. Строгая проверка неизвестных полей,
атомарность `setSettings`, публичный формат данных, события 1С и production-контракт остаются прежними.

Кнопка темы имеет `aria-pressed="true"` только для тёмного режима. Её `title` и `aria-label` равны
`Включить тёмную тему` либо `Включить светлую тему` и описывают следующее действие.

## 5. Критерии приёмки

- [ ] Светлая тема используется по умолчанию и визуально не меняется.
- [ ] API и кнопка синхронно переключают тему и доступные атрибуты кнопки.
- [ ] Тёмная палитра покрывает таблицы, состояния строк, панели, меню, сообщения и полосы прокрутки.
- [ ] Settings v1 сохраняет и восстанавливает тему, а старые снимки без `theme` продолжают применяться.
- [ ] Ошибки API и настроек не меняют действующую тему частично.
- [ ] `setData`, `init` и `destroy` соблюдают контракт сброса темы.
- [ ] Unit/browser-тесты и production-проверки проходят на ES2015 single-file сборке.

## 6. Вне области

- Автоматический выбор темы по `prefers-color-scheme` или настройкам операционной системы.
- Дополнительные темы, произвольные палитры и настройка отдельных цветов через API.
- Изменение существующего API пользовательских цветов ячеек.
