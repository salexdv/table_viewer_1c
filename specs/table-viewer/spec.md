# table-viewer: Single-file просмотрщик таблиц и деревьев для 1С

## 1. Контекст и проблема

1С передаёт сериализованные таблицы и деревья значений в «Поле HTML документа». Нужен автономный интерфейс,
который позволяет исследовать большие наборы данных, не обращается к сети и сообщает 1С о ссылках и экспорте.

## 2. Область изменений

Создаётся SPA на модульном JavaScript и CSS, production-сборка Webpack, модель таблиц/деревьев, виртуальный grid,
мост событий, тесты и документация интеграции.

## 3. Поведение

### 3.1. Основной сценарий

1. При загрузке приложение разбирает строгий JSON из `#data` и строит несколько таблиц друг под другом.
2. Пользователь сортирует и фильтрует данные, настраивает колонки, раскрывает дерево, меняет масштаб и ширину.
3. Контекстное меню фиксирует строки/колонки или устанавливает точный отбор.
4. Выделение прямоугольного диапазона показывает сумму распознанных чисел; строка итогов суммирует видимые узлы.
5. Клик ссылки и команда экспорта формируют события для 1С.

### 3.2. Данные и дерево

- `Data = { tables: Table[] }`.
- `Table = { name: string, columns: string[], rows: Row[] }`.
- `Row = { columns: Cell[], children?: Row[] }`.
- `Cell = string | number | boolean | null | { label: string, ref: string }`.
- Число ячеек строго совпадает с числом колонок.
- Непустой `children` в любом узле переводит таблицу в режим дерева; пустой массив означает лист.
- Сортировка стабильна и выполняется среди соседей. Дерево нумеруется как `1`, `1.1`, `1.1.1`.
- Фильтр показывает совпадение и цепочку предков. Глобальный поиск учитывает скрытые колонки.

### 3.3. Числовые данные

Автоопределение различает числа, проценты, даты `ДД.ММ.ГГГГ [ЧЧ:ММ:СС]` и текст. Поддерживаются пробелы,
запятая/точка и минус; строки с ведущими нулями считаются текстом. Итоги учитывают только реально видимые узлы.

### 3.4. Граничные случаи и ошибки

- JSON разбирается только через `JSON.parse`; ошибка отображается с путём к полю.
- Пустой набор показывает пустое состояние.
- Значения выводятся только как текст. Символ `<` при вставке JSON в HTML кодируется как `\u003C`.
- До 10 000 видимых узлов обрабатываются виртуализацией с ограниченным числом DOM-строк.

## 4. Публичные контракты

На `window` доступны `init`, `setData`, `setTableCollapsed`, `setTreeExpanded`, `expandAll`, `collapseAll`,
`sendEvent`, `fireEvent` и `destroy`.

`sendEvent(name, params)` ставит `{ event: name, params }` в `window.events_queue`, затем кликает
`#event-button`; обработчик добавляет объект в `clickEvent.eventData1C`.

| Событие | Payload |
| --- | --- |
| `EVENT_ON_LINK_CLICK` | `{ label, href }` |
| `EVENT_EXPORT` | `{}` |

Production-контракт: `dist/index.html` — единственный файл, JS/CSS инлайнены, плейсхолдер `_DATA_` сохранён,
синтаксис не выше ES2015.

## 5. Критерии приёмки

- [ ] Несколько плоских таблиц и деревьев произвольной глубины отображаются друг под другом.
- [ ] Работают сортировка, колонковые и глобальный фильтры, перенумерация и раскрытие путей совпадений.
- [ ] Работают видимость и resize колонок, несколько фиксированных строк/колонок, точный отбор.
- [ ] Работают выделение диапазона, сумма, итоги видимых строк, масштаб и сворачивание.
- [ ] Ссылка и экспорт создают документированные события 1С.
- [ ] Виртуализация держит ограниченное число DOM-строк на fixture из 10 000 узлов.
- [ ] Unit- и browser-тесты проходят; production содержит один автономный HTML уровня ES2015.
- [ ] README ссылается на документацию публичного API и интеграции 1С.

## 6. Вне области

- Генерация экспортируемого файла.
- Хранение настроек между загрузками.
- Серверная часть, сеть, аутентификация, Sites-хостинг и EPF-обработка.
