# table-viewer-layout-performance: Компактные команды, адаптивная компоновка и быстрый скролл

## 1. Контекст и проблема

Текстовые команды раскрытия занимают много места, кнопка экспорта пока не должна показываться, а рассчитанные
ширины колонок оставляют значительную незаполненную часть широкого окна. Единственная большая таблица ограничена
58% высоты окна. Виртуальное тело при любом событии прокрутки полностью удаляет и заново создаёт видимые строки,
ячейки и обработчики, что особенно заметно в HTML-поле 1С.

## 2. Область изменений

Изменяются панель команд, расчёт фактических размеров grid, управление высотой таблиц, виртуализация DOM-строк,
обработчики ячеек, browser smoke и документация поведения. Входные данные и интеграционные контракты не меняются.

## 3. Поведение

### 3.1. Компактные команды

- Глобальные команды `Развернуть все` и `Свернуть все` показывают только пиктограммы с двойными шевронами.
- Команды `Раскрыть дерево` и `Свернуть дерево` показывают только пиктограммы дерева с плюс/минус.
- Каждая пиктограммная кнопка сохраняет русские `title` и `aria-label`; её SVG скрыт от accessibility tree.
- Кнопка `Экспорт` остаётся в DOM и сохраняет обработчик `EVENT_EXPORT`, но временно скрыта отдельным CSS-классом.

### 3.2. Адаптивная ширина

- Начальные базовые ширины по-прежнему вычисляются по заголовку и данным с существующими пределами.
- Если сумма базовых ширин видимых колонок меньше ширины grid, свободное место пропорционально распределяется
  между колонками данных. Колонка нумерации не растягивается.
- Если базовые ширины не помещаются, они не сжимаются и доступна горизонтальная прокрутка.
- Ручной resize изменяет базовый вес колонки; оставшееся место продолжает пропорционально распределяться.
- Фактические ширины, полный размер строк и смещения закреплённых колонок обновляются после монтирования, изменения
  масштаба, видимости колонок, ручного resize и размера окна.

### 3.3. Адаптивная высота

- Если видна ровно одна развёрнутая таблица, её viewport занимает доступное место до нижнего края окна, но не
  превышает естественную высоту содержимого.
- Если видимая таблица короткая, пустое пространство внутри неё не добавляется.
- При нескольких видимых таблицах сохраняется ограничение 58% высоты окна и максимум 620 пикселей.
- Таблица, чья карточка видна, но grid свёрнут, учитывается при подсчёте видимых таблиц.
- Режим пересчитывается после глобального поиска, раскрытия таблицы и изменения размера окна.

### 3.4. Виртуальный скролл

- Обработка прокрутки объединяется до одного вызова на кадр через `requestAnimationFrame` с совместимым fallback.
- Горизонтальная прокрутка и вертикальное движение внутри неизменного диапазона не меняют DOM-строки.
- Виртуальное тело содержит ограниченный пул строк. Узлы переиспользуются и переназначаются строкам, вошедшим в
  окно; быстрый переход обновляет пул без его полной пересборки.
- Повторяющиеся события выбора и контекстного меню обслуживаются делегированием от grid-контейнера.
- Изменение выделения обновляет классы уже отрисованных ячеек без повторного создания строк.

### 3.5. Граничные случаи и ошибки

- При отсутствии видимых колонок растягивается только фон grid; ширина нумерации остаётся корректной.
- Изменение набора строк, колонок или масштаба сбрасывает виртуальный пул перед его следующим заполнением.
- Закреплённые строки не входят в прокручиваемый пул и сохраняют прежнее поведение.
- Все пользовательские данные продолжают выводиться только через `textContent`.

## 4. Публичные контракты

Форматы `Data`, функции `window.*`, очередь `{ event, params }` и события 1С не меняются. `EVENT_EXPORT` остаётся
поддержанным. Production остаётся автономным `dist/index.html` уровня ES2015 без внешних ресурсов.

## 5. Критерии приёмки

- [x] Четыре команды раскрытия не содержат видимого текста, имеют понятные пиктограммы и доступные подписи.
- [x] Кнопка экспорта скрыта, остаётся в DOM и продолжает отправлять `EVENT_EXPORT` при программном вызове.
- [x] Неполная по ширине таблица заполняет viewport пропорционально, переполненная сохраняет горизонтальный скролл.
- [x] Ручной resize, масштаб, видимость колонок, закрепление и resize окна корректно пересчитывают геометрию.
- [x] Одна видимая большая таблица занимает доступную высоту, короткая не растягивается, несколько таблиц
  сохраняют прежний предел.
- [x] Прокрутка сохраняет ограниченное число DOM-строк и переиспользует их без полной пересборки.
- [x] Ссылки, дерево, контекстное меню, закрепление и выделение работают после делегирования событий.
- [x] Unit- и browser-тесты проходят; сборка остаётся self-contained и совместимой с ES2015.

## 6. Вне области

- Изменение входной схемы, публичного API или контрактов событий 1С.
- Сохранение размеров и настроек между загрузками документа.
- Виртуализация колонок или одновременная компоновка нескольких таблиц на всю высоту окна.
