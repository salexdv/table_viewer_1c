# search-highlighting-and-clear: Поиск по фрагментам, подсветка и надёжная очистка

## 1. Контекст и проблема

Глобальный поиск и текстовые фильтры колонок ищут только цельную подстроку и не показывают место совпадения.
Встроенные кнопки очистки `input[type="search"]` в WebKit поля HTML документа 1С могут изменить значение без
событий `input` и `search`, из-за чего применённый поиск или фильтр остаётся активным.

## 2. Область изменений

Изменяются сопоставление текстовых запросов, безопасная отрисовка ячеек, элементы управления поиском, стили,
автоматические тесты и документация интеграции. Публичный JavaScript API, события 1С и формат данных не меняются.

## 3. Поведение

### 3.1. Поиск по фрагментам

- Глобальный поиск и текстовый фильтр колонки обрезают запрос и делят его по одному или нескольким пробельным
  символам.
- Сравнение регистронезависимое и выполняется по частичным вхождениям.
- Все фрагменты должны встретиться в одной ячейке в порядке запроса; между ними разрешён произвольный текст.
- Фрагменты из разных ячеек не объединяются. Глобальный поиск сохраняет строку, если полному запросу соответствует
  хотя бы одна ячейка, включая скрытую.
- Точные фильтры, фильтры выбранных значений и объединение разных видов фильтрации сохраняют текущую семантику.

### 3.2. Подсветка

- В видимой ячейке, полностью соответствующей глобальному или её колонковому запросу, подсвечиваются все
  вхождения фрагментов соответствующего запроса.
- Пересекающиеся и соприкасающиеся диапазоны подсветки объединяются.
- Если строка дерева показана только как предок найденного потомка, её ячейки не подсвечиваются без собственного
  полного совпадения.
- Подсветка работает для простых и ссылочных ячеек, не меняя ссылочный контракт и обработку клика.
- Пользовательские данные вставляются только через `textContent` или текстовые DOM-узлы.

### 3.3. Очистка

- Глобальный поиск, текстовые фильтры колонок и поиск значений получают собственные кнопки очистки.
- Кнопка показывается только при непустом поле, имеет доступное имя, очищает значение напрямую и немедленно
  запускает штатное обновление независимо от событий встроенного WebKit.
- Нативная кнопка очистки поискового поля не используется.

### 3.4. Граничные случаи и ошибки

- Пустой или состоящий только из пробелов запрос отключает соответствующий текстовый фильтр.
- Повторяющийся фрагмент должен быть найден повторно после предыдущего вхождения.
- Скрытая совпавшая колонка сохраняет строку в глобальном результате, но не создаёт видимой подсветки.
- Виртуализированные DOM-строки полностью пересчитывают подсветку при переиспользовании.

## 4. Публичные контракты

Публичные функции на `window`, `{ event, params }`, `window.events_queue`, `#event-button` и формат автономной
production-сборки остаются без изменений.

## 5. Критерии приёмки

- [x] `Управ тор` находит `Управление торговлей`, но не совпадает с обратным порядком или фрагментами в разных
  ячейках.
- [x] Совпадения общего и колонкового поиска подсвечиваются в обычных и ссылочных ячейках.
- [x] Служебные предки дерева не получают ложную подсветку.
- [x] Все три собственные кнопки очистки работают без отправки `input` или `search`.
- [x] Unit- и browser-тесты проходят, production остаётся автономной и соответствует ES2015.
- [x] Ручной чек-лист для поля HTML документа 1С 8.3.14+ дополнен проверками нового поведения.

## 6. Вне области

- Нечёткий поиск, изменение порядка фрагментов и объединение фрагментов из разных колонок.
- Подсветка в списке значений и изменение его текущей семантики поиска.
- Новые публичные методы или события 1С.
