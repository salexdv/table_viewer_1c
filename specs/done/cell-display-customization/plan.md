# cell-display-customization: план реализации и решения

## 1. План реализации

1. Добавить в модель чистые функции для типизированных ключей, распознавания пустых ссылок и вычисления
   визуального представления с заданным приоритетом правил.
2. Хранить настройки в `ViewerApp`, валидировать CSS-цвета и перерисовывать таблицы после успешных изменений.
3. Использовать вычисленное представление в обычных, виртуальных и закреплённых ячейках без изменения операций
   над исходными данными и событий 1С.
4. Экспортировать пять функций на `window` и описать их в документации API и интеграции.
5. Добавить unit-тесты правил и browser smoke жизненного цикла, безопасности, кликов и обратной совместимости.
6. Выполнить `npm test`, перевести спецификацию в `done` и перенести её в `specs/done/`.

## 3. Решения

| Дата | Решение | Причина |
| --- | --- | --- |
| 2026-09-15 | Сопоставлять точные значения по типу и значению | Не смешивает число `0` и строку `"0"` |
| 2026-09-15 | Оставить поиск, фильтры, сортировку, итоги и события на исходных данных | Настройка является только визуальной |
| 2026-09-15 | Сохранять настройки при `setData`, но сбрасывать при новом экземпляре | Соответствует жизненному циклу других настроек интеграции |
| 2026-09-15 | Показывать пустую ссылку обычным текстом | Пустой объект нельзя открывать в 1С |
| 2026-09-15 | Использовать `null` для удаления правил | Не требует дополнительных публичных функций очистки |
