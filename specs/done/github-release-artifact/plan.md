# github-release-artifact: план реализации и решения

## 1. План реализации

1. Зафиксировать и согласовать контракт публикации HTML-сборки.
2. Добавить GitHub Actions workflow с релизным и ручным триггерами.
3. Установить зависимости через npm, выполнить существующую production-сборку и подготовить
   `table_viewer.html`.
4. Разделить публикацию: GitHub Release asset для релизного события и Actions Artifact для ручного запуска.
5. Описать доставку готового файла в README.
6. Выполнить локальную сборку, проверить workflow и завершить спецификацию.

## 2. Открытые вопросы

Нет. Имя файла и оба режима запуска утверждены пользователем.

## 3. Решения

| Дата | Решение | Причина |
| --- | --- | --- |
| 2026-09-16 | Публиковать `table_viewer.html` | Стабильное понятное имя продукта для пользователя релиза |
| 2026-09-16 | Запускать workflow по `release.published` | Файл должен появляться только у опубликованного релиза |
| 2026-09-16 | Оставить `workflow_dispatch` | Ручной запуск позволяет проверить сборку без изменения релиза |
| 2026-09-16 | При повторной загрузке заменять asset | Повторный запуск должен быть идемпотентным по имени файла |
| 2026-09-16 | Использовать Node.js 20 и `npm ci` | Это минимальная версия проекта и воспроизводимая установка из lock-файла |
| 2026-09-16 | Спецификация утверждена пользователем | Пользователь явно запросил реализацию согласованного плана |

## 4. Результаты проверки

- `npm ci --no-audit --no-fund` установил 646 пакетов по `package-lock.json`; локальный Node.js 18 вывел
  ожидаемое предупреждение о требовании Node.js 20+, а workflow явно использует Node.js 20;
- YAML workflow успешно разобран, программная проверка подтвердила оба триггера, `npm run build`, загрузку в
  релиз с `--clobber` и ручной Actions Artifact;
- `npm run build` создал единственный `dist/index.html` размером 101 242 байта, проверки автономности и ES2015
  прошли;
- копирование в `table_viewer.html` проверено побайтовым сравнением;
- GitHub-hosted запуски `workflow_dispatch` и `release.published` станут доступны после отправки workflow в
  GitHub и проверяются первым ручным запуском и следующим опубликованным релизом.
