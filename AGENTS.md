# Правила работы с table_viewer

## Назначение

Проект собирает автономный HTML-просмотрщик таблиц и деревьев значений для «Поля HTML документа» 1С 8.3.14+.
Код, комментарии, спецификации и документация ведутся на русском языке.

## SDD

Любая новая функция, изменение поведения, публичного API, событий 1С или формата сборки начинается со
спецификации в `specs/<id>/spec.md` и плана в `specs/<id>/plan.md`.

Статусы: `draft` → `approved` → `in-progress` → `done`. Код разрешено менять только после `approved`.
Расхождение реализации со спецификацией исправляется в том же коммите. Завершённая спецификация переносится
в `specs/done/<id>/`.

## Ограничения реализации

- Публичные функции интеграции экспортируются непосредственно на `window`.
- Обратный мост 1С сохраняет контракт `{ event, params }` в `window.events_queue` и передаёт его через
  `clickEvent.eventData1C` скрытой кнопки `#event-button`.
- Production-сборка — один self-contained `dist/index.html`, без внешних ресурсов и сетевых запросов.
- ES-floor — ES2015. Не использовать optional chaining, nullish coalescing и API, отсутствующие в старом WebKit,
  без совместимого fallback.
- Данные выводятся только через `textContent`; запрещены `eval`, `Function` и вставка пользовательского HTML.
- Состояние интерфейса живёт только в памяти документа.

## Команды

- `npm run dev` — webpack-dev-server.
- `npm run build` — production single-file сборка и её проверка.
- `npm run test:unit` — unit-тесты модели.
- `npm run test:browser` — интеграционный smoke в Chromium.
- `npm test` — полный локальный гейт.

Перед коммитом запускать релевантные проверки. После каждого значимого завершённого этапа создавать отдельный
коммит с сообщением Conventional Commits.
