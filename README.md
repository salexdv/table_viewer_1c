# Table Viewer для 1С

Автономный single-page просмотрщик таблиц и деревьев значений для встраивания в «Поле HTML документа»
1С 8.3.14+. Приложение не требует сервера и runtime-зависимостей: production-сборка состоит из одного
минифицированного `dist/index.html` со встроенными JavaScript и CSS.

![](https://github.com/salexdv/git_images/blob/master/table_viewer.png?raw=true) 

## Возможности

- несколько таблиц и деревьев неограниченной практической глубины;
- сортировка среди соседних узлов, текстовые фильтры, фильтры по списку значений и глобальный поиск;
- переиспользуемая виртуализация до 10 000 узлов, нумерация строк и настраиваемые итоги;
- автоподбор, пропорциональное заполнение свободной ширины и ручной resize колонок, включая нумерацию;
- глобальный переключатель переноса длинных значений на строки с автоматической высотой;
- адаптивная высота одной видимой таблицы, фиксация колонок и строк;
- раскрытие деревьев, сворачивание таблиц и масштаб 50–200%;
- JSON/API для сохранения и восстановления масштаба, порядка и параметров колонок, фиксации и всех фильтров;
- светлая и тёмная темы с переключением из панели, JavaScript API и сохранением в настройках;
- прямоугольное выделение ячеек и popup `Ʃ` с суммой, средним, минимумом, максимумом и количеством;
- контекстное скрытие выделенных строк и диапазонов с маркерами восстановления;
- быстрые кнопки и контекстный выбор уровня группировки дерева от корней до полного раскрытия;
- события перехода по ссылке, пользовательские команды и подменю контекстного меню, экспорт через совместимый
  с 1С мост;
  кнопка экспорта временно скрыта;
- строгая валидация JSON с указанием пути к ошибочному элементу.

## Установка и сборка

Требуется Node.js 20+ с npm.

```bash
npm install
npm run build
```

Готовый файл находится в `dist/index.html`. Команда сборки дополнительно проверяет, что HTML единственный,
не содержит внешних ресурсов, сохраняет `_DATA_`, а inline JavaScript разбирается как ES2015.

При публикации [GitHub Release](https://github.com/salexdv/table_viewer_1c/releases) проект автоматически
собирается, а к релизу прикладываются готовый `table_viewer.html` и тестовая обработка 1С
`TestTableViewer.epf`. Workflow также можно запустить вручную на вкладке Actions: в этом случае файлы
сохраняются в Actions Artifacts `table_viewer-html` и `test-table-viewer-epf`, не изменяя релизы.

## Выпуск релизов

Версии формируются [Release Please](https://github.com/googleapis/release-please) из сообщений коммитов по
соглашению [Conventional Commits](https://www.conventionalcommits.org/):

- `fix:` повышает patch-версию (`1.0.0` → `1.0.1`);
- `feat:` повышает minor-версию (`1.0.0` → `1.1.0`);
- `feat!:`, `fix!:` или footer `BREAKING CHANGE:` повышает major-версию (`1.0.0` → `2.0.0`).

После появления пользовательских изменений Release Please создаёт или обновляет Release PR с новой версией
и `CHANGELOG.md`. Слияние этого PR создаёт тег `vX.Y.Z`, публикует GitHub Release и запускает загрузку обоих
готовых файлов. `tests/TestTableViewer.epf` хранится в Git как бинарный файл: перед выпуском нужно обновить и
закоммитить обработку, чтобы она соответствовала релизному исходному коду.

Для работы Release Please в настройках репозитория GitHub Actions должно быть разрешено создавать pull
requests. Автоматическая публикация npm-пакета не выполняется.

Для разработки и проверок:

```bash
npm run dev
npm run test:unit
npm run test:browser
npm test
```

Browser smoke ищет Chromium/Chrome в системе или локальный Chrome Headless Shell в `.cache/puppeteer`.
При отсутствии браузера его можно установить командой:

```bash
npx @puppeteer/browsers@2.13.2 install chrome-headless-shell@stable --path .cache/puppeteer
```

## Формат данных

```json
{
  "tables": [
    {
      "id": "orders",
      "name": "Дерево заказов",
      "columns": [
        { "id": "link", "name": "Ссылка" },
        { "id": "number", "name": "Номер" },
        { "id": "date", "name": "Дата" },
        { "id": "amount", "name": "Сумма" }
      ],
      "rows": [
        {
          "columns": [
            {
              "label": "Заявка 000000001",
              "ref": "e1cib/data/Документ.ЗаявкаНаРемонт?ref=919568545aabd37511f1a9e4829851e5"
            },
            "000000001",
            "06.09.2026 14:18:01",
            "1 250,50"
          ],
          "children": [
            {
              "columns": ["Работа", "000000002", "07.09.2026 09:00:00", 850],
              "children": []
            }
          ]
        }
      ]
    }
  ]
}
```

Колонки можно по-прежнему задавать строками; объектная форма добавляет стабильный `id` для настроек. Ячейка
может содержать строку, конечное число, boolean, `null` или объект `{ "label": "…", "ref": "…" }`.
Число ячеек в каждой строке обязано совпадать с числом колонок. Непустой `children` хотя бы у одного узла
делает таблицу деревом; `children: []` обозначает лист. Хвостовые запятые недопустимы.

## Встраивание

В `dist/index.html` нужно заменить единственный маркер `_DATA_` сериализованным JSON. Перед подстановкой
обязательно заменить каждый символ `<` внутри JSON на `\u003C`, чтобы данные не могли преждевременно закрыть
элемент `<script>`.

```html
<script id="data" type="application/json">_DATA_</script>
<button id="event-button" hidden></button>
```

Страница сама вызывает `init()` после загрузки. Для последующей замены данных без перезагрузки используйте
`Документ.defaultView.setData(...)`.

## Совместимость и безопасность

Production-код ограничен ES2015 и ориентирован на старый WebKit в 1С 8.3.14+. Приложение не использует
`ResizeObserver`, внешние ресурсы, `eval` или исполнение HTML из данных. Значения ячеек выводятся через
`textContent`; URL из `ref` не открывается браузером, а передаётся в событии 1С.
